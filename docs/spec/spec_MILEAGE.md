# Спецификация MILEAGE

## Входит / не входит

**Входит:** проверка переданного пробега автомобиля при расчёте решения по заявке; сохранение текущего решения по LTV при пробеге не более порога; перевод в `review` при пробеге выше порога в определённых ниже случаях; валидация обязательности и допустимого диапазона пробега.

**Не входит:** цель изменения и сознательно исключённый объём не зафиксированы в intent; они перенесены в открытые вопросы этой спецификации. Реализация проверки, изменение LTV-порогов, изменение максимального и минимального допустимого пробега, а также выбор решения для сочетания пробега выше порога и LTV выше `85.0` не входят в подтверждённый объём.

## Требования

### REQ-MILEAGE-01. Решение при пробеге не выше порога

Для заявки с указанным допустимым пробегом не более `400000` км должно применяться текущее решение по LTV: менее `60.0` — `approve`, от `60.0` до `85.0` включительно — `review`, более `85.0` — `reject`.

Источник: порог `400000` км — ответ в интервью (`docs/intent/intent_MILEAGE.md`, строки 3 и 11); LTV-пороги `60.0` и `85.0` — код: `backend/src/Domain/DecisionEngine.php` (`docs/intent/intent_MILEAGE.md`, строка 14).

**AC-MILEAGE-01.** Given заявка с допустимым пробегом `399999` км и LTV, для которого текущий расчёт возвращает одно из решений `approve`, `review` или `reject`; When рассчитывается решение; Then возвращается то же решение по LTV без перевода в `review` из-за пробега. Ссылка: REQ-MILEAGE-01. Источник числа `399999`: граничное значение на один километр ниже порога `400000` км из ответа в интервью.

**AC-MILEAGE-02.** Given заявка с допустимым пробегом `400000` км и LTV, для которого текущий расчёт возвращает одно из решений `approve`, `review` или `reject`; When рассчитывается решение; Then возвращается то же решение по LTV без перевода в `review` из-за пробега. Ссылка: REQ-MILEAGE-01. Источник числа `400000`: ответ в интервью (`docs/intent/intent_MILEAGE.md`, строки 3 и 11).

### REQ-MILEAGE-02. Решение при пробеге выше порога

Для заявки с указанным допустимым пробегом более `400000` км и LTV не более `85.0` должно возвращаться решение `review`.

Источник: правило для пробега более `400000` км — ответ в интервью (`docs/intent/intent_MILEAGE.md`, строки 3 и 11); исключённое сочетание LTV более `85.0` — открытый вопрос intent (`docs/intent/intent_MILEAGE.md`, строка 18); число `85.0` — код: `backend/src/Domain/DecisionEngine.php` (`docs/intent/intent_MILEAGE.md`, строка 14).

**AC-MILEAGE-03.** Given заявка с допустимым пробегом `400001` км и LTV не более `85.0`; When рассчитывается решение; Then возвращается `review`. Ссылка: REQ-MILEAGE-02. Источник числа `400001`: граничное значение на один километр выше порога `400000` км из ответа в интервью; источник числа `85.0`: код: `backend/src/Domain/DecisionEngine.php`.

### REQ-MILEAGE-03. Допустимый диапазон пробега

Расчёт решения должен выполняться только для указанного пробега от `0` до `500000` км включительно; при значении меньше `0` или больше `500000` км заявка не проходит валидацию и решение не рассчитывается.

Источник чисел `0` и `500000`: код: `backend/src/Domain/ApplicationValidator.php` (`docs/intent/intent_MILEAGE.md`, строка 12).

**AC-MILEAGE-04.** Given заявка с пробегом `0` км; When выполняется валидация; Then заявка проходит проверку пробега и расчёт решения может быть выполнен. Ссылка: REQ-MILEAGE-03. Источник числа `0`: код: `backend/src/Domain/ApplicationValidator.php`.

**AC-MILEAGE-05.** Given заявка с пробегом `500000` км; When выполняется валидация; Then заявка проходит проверку пробега и расчёт решения может быть выполнен. Ссылка: REQ-MILEAGE-03. Источник числа `500000`: код: `backend/src/Domain/ApplicationValidator.php`.

**AC-MILEAGE-06.** Given заявка с пробегом `-1` км или `500001` км; When выполняется валидация; Then заявка не проходит валидацию и решение не рассчитывается. Ссылка: REQ-MILEAGE-03. Источник чисел `-1` и `500001`: граничные значения за пределами диапазона от `0` до `500000` км, заданного в `backend/src/Domain/ApplicationValidator.php`.

### REQ-MILEAGE-04. Пустой или неизвестный пробег

Если числовой пробег не указан, в том числе когда пробег неизвестен, заявка не проходит валидацию и решение не рассчитывается.

Источник: код: `backend/src/Domain/ApplicationValidator.php` (`docs/intent/intent_MILEAGE.md`, строка 13). В этой спецификации неизвестный пробег означает отсутствие указанного числового значения, поскольку иное представление неизвестного пробега в intent не зафиксировано.

**AC-MILEAGE-07.** Given заявка с пустым значением пробега; When выполняется валидация; Then заявка не проходит валидацию и решение не рассчитывается. Ссылка: REQ-MILEAGE-04. Источник: код: `backend/src/Domain/ApplicationValidator.php`.

**AC-MILEAGE-08.** Given заявка с неизвестным пробегом без числового значения; When выполняется валидация; Then заявка не проходит валидацию и решение не рассчитывается. Ссылка: REQ-MILEAGE-04. Источник: код: `backend/src/Domain/ApplicationValidator.php`; трактовка неизвестного значения как неуказанного — ограничение данных intent.

## Открытые вопросы из intent

1. **Перенесён в эту спецификацию, риск-менеджмент:** для пробега более `400000` км и LTV более `85.0` выбрать `review` или `reject`. До решения этот случай исключён из REQ-MILEAGE-02.
2. **Перенесён в эту спецификацию, владелец не определён:** какую проблему решает изменение. В intent ответ не зафиксирован.
3. **Перенесён в эту спецификацию, владелец не определён:** что сознательно остаётся за рамками изменения. В intent ответ не зафиксирован.
